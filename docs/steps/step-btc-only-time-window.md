# Step — momentum 收口为 BTC-only + 时间窗 25→35min

## 概要

把 momentum_follow 收口成**只做 BTC**(其余币种全部退出),并把入场时间窗下沿从 25min 收到 35min。入场价带 [0.64, 0.79] 维持不变(经多源数据复核确认是对的)。延续 [[momentum-band-postmortem]] 的逐币收口计划——这一步直接走到终点:除 BTC 外全砍。

## 背景:逐币复核后的结论

`5a33bad`(0.84 全币种扩宽)上线后整体胜率从 88% 崩到 44-54%。逐币 + 多源数据复核(dry-run,仓位级,按 entry_time 去重):

- **DOGE**:34 仓 / 26% 胜 / 净 −2.38,**每个价带都负 EV**——最大失血源。
- **ETH**:净 −0.17(打平偏负),仅 0.74-0.79 子带正。
- **XRP**:净 +0.58,正但样本不稳。
- **BTC**:唯一跨时段稳定正 EV 的币(合并 66-77 市场小时,67% 胜 / EV +0.04-0.05)。

user 决策:只留 BTC,其余全退。

## 两处改动

### ① 只做 BTC(`coin_ != "BTC"` 守卫)

原 `coin_ == "SOL"` 过滤改成 `coin_ != "BTC"`,ETH/XRP/DOGE/BNB 全部 reject(`momentum_coin_filter`)。对 BTC 自身的交易行为**零影响**,只是踢掉其余币。

### ② 时间窗 25→35min

`minutes_remaining < 25` 改成 `< 35`。依据:**跨币池化** <35min 入场 36 仓 / 36% 胜 / 净 −1.28 / **p=0.018 显著**;机制清晰——剩余 <35min 动量来不及走到 TP 就到期结算。

**把握分级(诚实记录)**:
- "<35min 入场差"本身:高把握(显著 + 有机制)。
- "BTC 也适用":中等把握,靠跨币外推——BTC 在保留带内历史上 0 笔 <35min 入场,无法用 BTC 自身数据证明。
- 但对 BTC **零成本**(历史砍掉 0 笔),是纯防御安全栏:下了挡住一类必亏入场,外推错了也不亏。

### 连带:简化上沿代码

只剩 BTC 后 `entry_upper = (coin_=="BTC")?0.79:0.84` 退化为统一 `0.79`;非 BTC 的 `abs_dev<0.24` 分支成死代码,一并删除。入场带逻辑等价不变。

## 上沿 0.79 复核(本步未改,但确认正确)

被问到"0.79 改对没"时做了专项复核。两条独立证据:

1. **利润拐点**(77 市场小时,跨主策略+实验池化):cap 0.79 净 +2.61 > 保留 0.84 的 +2.43,且胜率/EV 全面更高;再往下 cap 0.73/0.69 净反而掉(丢掉赚钱的 0.74-0.79 带)。0.79 是利润最大化拐点。
2. **TP 封顶机制**(决定性):TP=`min(0.88,E+0.08)`,E≥0.81 起赢的毛利被压扁而输仍是全本金。E=0.84 时拿 0.84 赌 0.04(R:R=0.05),需 ~95% 胜率才保本——纯价格数学,跟币种/样本无关。

对照反例:曾考虑砍 0.70-0.74"死区"(主样本 7 仓 43%),但样本扩到 66 仓后回到 56%/正 EV,证明是小样本噪音,**未采纳**。死区无机制、扩样本翻盘;0.79 有机制、扩样本更稳——这是两者置信度的本质区别。

## 设计决策

- **BTC-only 而非保留 XRP**:XRP 净 +0.58 是正的,但样本不稳;user 选择最稳路线。后续若觉空仓太多想加量,正确做法是按同样 0.79 上沿把 XRP 放回来,而非放宽 BTC 闸门。
- **时间窗收 35 而非更激进**:跨币数据显示 35-45min 才转正,35 是数据拐点。
- **入场带保持 0.64-0.79 不细切**:66-77 仓撑不起子带级切割(已被 0.70-0.74 死区翻盘教训证明)。
