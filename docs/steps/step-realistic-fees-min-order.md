# Step — 真实化手续费 + 最小单（主策略 + 全部实验）

## 概要

让主策略和全部 5 个影子实验的**模拟下单**贴合 Polymarket 真实规则：手续费率改成官方分类费率（Crypto 7% / Finance 4%），入场份额托到交易所最小单（限价单 ≥5 股且名义额 ≥$1），部分止盈凑不满 $1 时一次性清掉剩余整仓（dust 规则）。**只动下单执行 + 记账层，策略决策逻辑（入场/止盈/止损判断）一行未改。**

## 背景：核对官方文档

- 费率（docs.polymarket.com/trading/fees，2026-03）：`fee = shares × rate × p × (1-p)`，**只有 taker 付费、maker 免费**。分类费率 Crypto **0.07**、Finance **0.04**（本 bot 只涉及这两类）。官方例 `100 股 @0.50 → $1.75` 对得上。
- 最小单（help.polymarket.com）：**市价单 ≥$1 名义额；限价单 ≥5 股**。
- 真实成交核对：本地 14 笔 live 单**入场费全为 0**，证实挂的 `ask−1¢` 限价单以 maker 成交 → 入场 maker 免费的建模是对的。

## 设计决策

1. **入场用限价 maker（免费），不改市价**。核对历史发现：改市价 taker 入场会让每笔先被抽 ~5% + 1¢ 滑点，把 BTC 从打平砸成 −$7.10/67 仓；而限价 maker（bot 本来就这么建模、也符合真实成交）下 BTC/ETH 仍为正。故保留限价入场，只修费率与最小单。
2. **入场份额下限 = `max(5 股, $1/入场价)`**。同时满足"限价单≥5 股"和"持仓名义额≥$1（否则离场市价卖单<$1 卖不掉）"。只改仓位**绝对规模**，不改任何决策；因费率按比例收，放大仓位不改变"赚不赚"的结论。
3. **dust 规则 = 卖不满 $1 → 清剩余整仓**。部分止盈时若这一档卖出或卖后剩余 <$1（现实下不出小单），就一次性清掉剩余。这是唯一会让"执行结果"略偏离字面 TP 比例的地方——但它是现实约束（$0.4 的卖单根本下不出），不是改策略。历史里约 12% 的仓位（有 tp1/tp2 的）受影响：尾仓改成一次清而非分批。
4. **范围 = 主策略 + 全部 5 个实验**，口径统一可比。费率/最小单逻辑落在共享的下单/记账块，finance 实验单独用 0.04。
5. **strategy.cpp 零改动**。已核实其入场/止盈/止损判断只读价格/时间/regime，从不读费率或仓位大小；最小单与 dust 规则全部落在 main.cpp / experiment_engine.cpp 的执行层。

1. **影响 live 实盘下单规模**：入场份额托底落在主策略共享路径，部署到服务器后会让 live 真单也 ≥5 股（之前 $1 名义在 >0.20 价位只有 <5 股，本会被交易所拒——顺带修了，但 live 仓位会比"$1 名义"略大，需知会）。
2. **dust 规则改约 12% 仓位的尾仓平法**（已与 user 确认接受）。
3. **本地 trades.jsonl 已旧**（近 14 天无新数据，混多版本/币种），上面数字是指示性而非当前配置定论；要更准需到服务器（159.203.56.165）拉近期同配置单重算。
4. **到期结算价仍按 last_bid（主策略）**：真实到期会结算到 0/1。本步未动（不在"最小单+手续费"范围内），实验引擎已是 0/1 结算。
