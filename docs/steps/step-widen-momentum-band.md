# Step — momentum_follow 入场区间从 [0.64, 0.67] 扩到 [0.64, 0.84]（含回测 + 5 项稳健性检查）

**日期**：2026-05-26
**改动**：`strategy.cpp` evaluate_momentum_follow 一行——`entry_price > 0.67` 改成 `entry_price > 0.84`。
**预期**：6-10x 频率提升，BTC-only 子集回测 EV/笔 ~+$0.10，每日均正。

---

## 为什么改

退役 QR 后主策略只剩 momentum。但 momentum 在新 30h（05-25 ~ 05-26）**0 次入场**——934 个 BTC/ETH 趋势带候选全被 `momentum_entry_range` 拒掉，**真实 favored 侧 ask 84% 已经 ≥ 0.85**（深入价内）。原 3¢ 窄缝 [0.64, 0.67] 只捕捉行情**刚启动的几秒**，dev≥0.20% 的强趋势在 25-44min 时间窗内通常已被定价到 0.70-0.95。

## 怎么改

```cpp
// strategy.cpp L290:
- if (entry_price < 0.64 || entry_price > 0.67) {
+ if (entry_price < 0.64 || entry_price > 0.84) {
```

其余 momentum 规则**全部保留**：BTC 要 dev≥0.20%、非 BTC 要 dev≥0.24%、spread≤1¢、mr 25-44、单笔 $1.00。TP/stop/trailing 全部不动。

## 为什么是 0.84，不是 0.95

TP 规则 `tp0 = min(0.88, E + 0.08)` 在高价区被强行 cap。在真实 TP/stop 模型下逐 entry 算赔付：

| entry | win 赔付 | loss 赔付 | 备注 |
|---|---|---|---|
| 0.65 | **+$0.169** | −$0.108 | 健康 |
| 0.75 | +$0.147 | −$0.093 | 健康 |
| 0.80 | +$0.113 | −$0.088 | TP1 开始被 cap |
| **0.83** | **+$0.072** | −$0.084 | TP0、TP1 都被 cap |
| 0.85 | +$0.047 | −$0.082 | 胜的赔付 < 输的赔付 |
| 0.88 | +$0.011 | −$0.080 | 几乎等于 0 |
| 0.90 | **−$0.011** | −$0.078 | ⚠ **胜也亏** |

**0.85 是数学终点**——再往上 TP0 cap 在 0.88 反而低于 entry，"止盈"瞬间触发亏损。0.84 是保守安全边距。

> ⚠ **给未来**：任何想把入场上沿推到 0.85+ 的人，必须先重做 TP 规则（去掉 `min(0.88, ...)` cap）。否则 0.85+ entries 一开仓就处于 TP0 触发状态、立即按 0.88 平 50% = 立即亏损。

## 回测方法

- **数据源**：`logs/main_candidates.jsonl`（111,905 行候选，2026-05-20 ~ 05-26，~6 天）
- **市场聚合**：`(coin, expiry_hour)` 近似 market_id（候选日志无 condition_id）
- **结果代理**：每个市场 mr ≤ 25 的最后 tick，看 `up_ask` vs `down_ask` 分离度；`|up_ask - down_ask| ≥ 0.30` 才认作清晰结果（94 个不清晰市场单独处理，见检查 B）
- **入场模拟**：对每个市场，找首个满足"mr 25-44 + dev ≥ 0.20%(BTC)/0.24%(其他) + spread ≤ 1¢ + entry ∈ [0.64, max_e]"的 tick
- **PnL 模型**：真实 TP/stop——胜：50% 卖在 `min(0.88, E+0.08)`，50% 卖在 `min(0.90, E+0.14)`；负：stop_price `-0.07/share`

## 5 项稳健性检查

### A. 真实 TP/stop 模型（替换我最初的 +$0.08/-$0.07 简化）

第一版用 +$0.08/-$0.07 flat 算 EV 是错的——TP cap 在高价区会大幅压缩赔付。改用 `winner_pnl(E) = 0.5×(min(0.88,E+0.08)-E)/E + 0.5×(min(0.90,E+0.14)-E)/E`、`loser_pnl(E) = -0.07/E` 后才有上表。

### B. 94 个"不清晰"市场用悲观假设灌回

放宽到 0.84 上限下，94 个 sep<0.30 的不清晰市场里**只有 10 个能入场**（大多数不清晰市场价格在 0.84 外）：

| 假设 | n | 胜率 | EV/笔 |
|---|---|---|---|
| 仅清晰（基线）| 71 | 90% | +$0.084 |
| 不清晰按 **50%** 胜率灌回 | 81 | 85% | **+$0.075** |
| 不清晰按 60% | 81 | 86% | +$0.077 |
| 不清晰按 70% | 81 | 88% | +$0.079 |
| 不清晰按 80% | 81 | 89% | +$0.082 |

**最悲观（50%）EV 仍 +$0.075/笔，结论不依赖结果代理的乐观假设。**

### C. 结果代理阈值敏感性

| sep_threshold | n | 胜率 | EV/笔 |
|---|---|---|---|

**EV 在 [0.20, 0.50] 全区间稳定在 +$0.083~+$0.093，不是 0.30 这个数撑起来的。**

## 用历史真实交易做模型校准

我用同一套真实 TP/stop 模型反算当前 15 笔 trend 实际位置：

- 模型预测：+$0.87
- 实际：+$0.55
- 比例：**模型偏乐观 ~1.5x**（实际有 momentum_faded 提前止损让损失更小、但 trailing 让胜也变小，两边都偏离两点 TP 假设）

**1.5x 折扣后保守估计**：

| | 模型 | 折扣后（保守）|
|---|---|---|
| EV/笔 | +$0.084 | **~+$0.055** |
| 净 PnL（71 笔 / 6 天）| +$5.99 | **~+$3.5** |
| 日均 PnL | $1.00 | **~$0.58** |

对比现网 trend：15 笔 / 10 天净 +$0.55 = **$0.055/天**。**保守估计的频率/收益提升 ≈ 10 倍。**

## 三条强制免责（部署前必读）

1. **TP 结构是约束，不是建议**：`tp0=min(0.88, E+0.08)` 这个 cap 决定了 0.85 是数学天花板。**任何往 0.85+ 扩的人必须先重做 TP 规则**——否则一开仓就触发 TP0 在 0.88、立即按 0.88 平 50% = 立即亏损。
2. **结果代理不是真到期**：用 mr≈21 时 favored vs 对手 ask 分离度 ≥ 0.30 判输赢。检查 C 已用 sep=0.20~0.50 全跑过、结论稳；但理论上有最后 21min BTC 反转的尾部风险，回测不能完全捕获。
3. **模型 1.5x 校准是历史平均**：未来不同行情段这个比例可能不一样。如果在新区间是 2x（即真实 EV 仅模型一半），仍正但收益减半。如果反转 ≥3x，可能转负——但目前没有证据支持这种极端情况。

## 遗留问题

- TP 规则适配 0.85+ 是潜在下一步立项（如果想进一步提频）；现在不动。
- 0.68-0.74 桶 67% 胜率比其他桶低；当前选择"简单连续区间"而不是"挖洞 [0.64,0.67]∪[0.75,0.84]"——前者 EV/笔 +$0.084，后者约 +$0.088，差距小、复杂度提升不值。
- main_candidates.jsonl 里 entry_price 字段对 momentum 入场区间外被拒的候选默认为 0（field-not-set bug）——影响诊断但不影响交易决策。下次改 momentum 时顺手把 `sig.entry_price = entry_price` 移到 entry_range 检查之前。
